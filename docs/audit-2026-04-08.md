## Per-Dimension Analysis

### 1. Architecture -- 4/5

**Strengths:**
- Clean three-layer separation: YAML clinical content / decision-engine-core runtime / Vue 3 UI
- Normalized Pinia store with entity maps (`questionnaireStore.ts:40-44`)
- PWA with prompt-based service worker updates (`vite.config.js:24`)
- Brotli + gzip compression (`vite.config.js:59-68`)
- Role system (`_role`) cleanly injected into condition evaluation (`questionnaireStore.ts:183-189`)

**Weaknesses:**
- decision-engine-core is a local tarball (`decision-engine-core-1.0.0.tgz`) with no version pinning, audit visibility, or documented update process
- Stale `.nuxt/` directory (13 files) cluttering root -- leftover from Nuxt migration, adds confusion and may be contributing `defu` dependency to vulnerability count

### 2. Security -- 3/5

**Strengths:**
- `.env` properly gitignored; CI verifies not tracked (`ci.yml:52-57`)
- CI secret scanning for JWT patterns (`ci.yml:46-51`)
- eslint-plugin-security enabled (`eslint.config.js:32`)
- Supabase auth for admin routes with router guard (`router/index.ts:91-99`)
- `npm audit --omit=dev` in CI with `continue-on-error: true` (`ci.yml:41-43`)

**Weaknesses:**
- **`.env` contains 3 unrelated API keys:** OPENAI_API_KEY, ANTHROPIC_API_KEY, DEEPSEEK_API_KEY (`src/lib/` does not reference any of these). If this file is ever leaked, three separate API accounts are compromised.
- **v-html used without sanitization:** `QuestionnairePage.vue:84,103` renders `marked.parse()` output directly into `v-html`. Input comes from YAML flows (trusted), but no DOMPurify layer protects against future malicious flow content.
- **`vue/no-v-html` eslint rule explicitly disabled** (`eslint.config.js:49`)
- **Source maps uploaded to Supabase Storage** (`ci.yml:118-140`) using service key -- bucket access control should be verified
- **15 dependency vulnerabilities** (13 high) -- while build-only, the Vite dev server CVEs (GHSA-4w7w-66w2-5vf9, GHSA-v2wj-q39q-566r, GHSA-p9ff-h696-f583) are exploitable during local development
- **Vite pinned to `7.2.4`** in package.json but fix available at `7.3.2` -- requires semver range update

### 3. Performance -- 5/5

**Strengths:**
- Brotli + gzip pre-compression for all assets above 1024 bytes
- Service worker with precaching (`workbox.globPatterns`)
- Lazy-loaded routes for QuestionnairePage and admin pages (`router/index.ts:21,75-76`)
- CSS containment (`ResultPage.vue:347 -- contain: layout style paint`)
- Skeleton loading states (`QuestionnairePage.vue:4-13`, `ResultPage.vue:23-49`)
- Cache-busted fetch for main.json (`questionnaireStore.ts:143 -- ?t=Date.now()`)
- Touch-optimized with `touch-action: manipulation` (`QuestionnairePage.vue:503`)
- Staggered entrance animations for result sections (`ResultPage.vue:657-684`)

No issues identified. Performance engineering is excellent for a clinical tool.

### 4. Reliability -- 3/5

**Strengths:**
- Unified error handler with classification (`errors.ts:14-45`) covering network, timeout, Supabase, and auth errors
- Structured logger with module filtering, sink system, and breadcrumbs (`logger.ts`)

**Weaknesses:**
- **Zero test files** -- `vitest` configured with `passWithNoTests: true` (`vite.config.js:19`). For a medical decision support tool used by healthcare professionals, this is a significant reliability gap.
- **No YAML validation tests** verifying specific clinical paths

### SPEC-UR03: Add DOMPurify sanitization for v-html

**Type:** Security hardening
**Impact:** High -- prevents potential XSS if YAML flow content is ever compromised
**Effort:** S (2 hours)

**Problem:** `src/views/QuestionnairePage.vue:84,103` -- `v-html="compiledMarkdown(...)"` renders `marked.parse()` output without sanitization. Line 347 defines `compiledMarkdown` as a direct `marked.parse()` call.

**Solution:** Install `dompurify` and wrap all `marked.parse()` output:

```typescript
import DOMPurify from 'dompurify'
const compiledMarkdown = (text: string | undefined): string =>
  text ? DOMPurify.sanitize(marked.parse(text) as string) : ''
```

**Acceptance Criteria:**

Given a YAML flow description contains `<script>alert('xss')</script>`
When the markdown is rendered in QuestionnairePage
Then the script tag is stripped from the output

Given a YAML flow description contains valid markdown with links
When the markdown is rendered
Then links are preserved and functional

**Checklist:**
- [ ] Install dompurify: `npm install dompurify`
- [ ] Install types: `npm install -D @types/dompurify`
- [ ] Wrap `marked.parse()` with `DOMPurify.sanitize()` in QuestionnairePage.vue
- [ ] Re-enable `vue/no-v-html` eslint rule or add inline comment explaining sanitization
