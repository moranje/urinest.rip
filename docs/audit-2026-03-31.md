## Dimension Analysis

### 1. Architecture (4/5)

**Strengths:**
- Clean separation: YAML flows (clinical content) vs. TypeScript engine (execution) vs. Vue components (presentation).
- Normalized Pinia store (`src/store/questionnaireStore.ts`) with flat lookup maps for questions, steps, results, and logic rules.
- Build-time YAML compilation via decision-engine-core Vite plugin eliminates runtime YAML parsing.
- Role-based condition injection (`_role`) cleanly separates triage vs. behandelaar pathways.
- Smart cross-flow redirects (strip -> bacteriurie, leukocyturie -> dipslide/sediment/kweek -> bacteriurie).
- Well-structured error handling pipeline: `errors.ts` -> `logger.ts` -> `log-sink.ts` -> Supabase.

**Remaining issues:**
- `src/store/questionnaireStore.ts:143`: Cache-busting via `Date.now()` query parameter defeats PWA caching of `main.json`. The service worker `globPatterns` includes `**/*.json`, so workbox-precached version and network-fetched version diverge.
- Single `main.json` monolith means any flow change invalidates the entire cached payload.
- The decision-engine-core is distributed as a local tarball (`decision-engine-core-1.0.0.tgz`) with no visible source, making updates opaque.

### 2. Security (4/5)

**Strengths:**
- CI pipeline includes secret scanning (JWT pattern grep), `.env` tracking check, and `npm audit`.
- Supabase anon key passed via environment variables, not hardcoded.
- ESLint security plugin configured.
- Admin routes protected by auth guard (`src/router/index.ts:91-99`).
- Source maps uploaded to private Supabase storage, not shipped to client.

**Remaining issues:**
- `src/views/QuestionnairePage.vue:85,103`: `v-html="compiledMarkdown(...)"` renders markdown as raw HTML. While YAML is author-controlled, `marked` does not sanitize by default. If build pipeline were compromised, XSS is possible.
- `npm audit` reports **12 vulnerabilities** (2 moderate, 10 high): `undici` (HTTP smuggling, memory DoS), `yaml` (stack overflow), `@rollup/plugin-terser` chain via `workbox-build`.
- `ci.yml:42-43`: `npm audit` runs with `continue-on-error: true`, so builds succeed despite high vulnerabilities.
- CI triggers on `master` branch (`.github/workflows/ci.yml:5-6`) but local branch is `main`. Potential branch mismatch.

### 3. Performance (4/5)

**Strengths:**
- Brotli and gzip compression via `vite-plugin-compression`.
- Code splitting: QuestionnairePage and admin views are lazy-loaded.
- CSS design tokens with custom properties, no runtime CSS-in-JS.
- Skeleton loading states in QuestionnairePage and ResultPage.
- `contain: layout style paint` for paint isolation (`src/views/ResultPage.vue:347`).

**Remaining issues:**
- `src/store/questionnaireStore.ts:143`: `fetch('/main.json?t=' + Date.now())` fires a network request every load, defeating browser and service worker caching.
- `marked` library (~17KB gzipped) imported for rendering short inline markdown descriptions. A lighter alternative could reduce bundle.

### 4. Reliability / Clinical Correctness (4/5) -- CRITICAL DIMENSION

**Strengths:**

*Flow coverage:*
- 8 flows covering strip, sediment, dipslide, kweek, hematurie, leukocyturie, gezonde vrouwen, and bacteriurie.
- Bacteriurie flow is the most complex: covers tissue invasion vs. local, 8 patient groups (healthy, vulnerable, elderly, pregnant, men, children, CAD, catheter), sex differentiation for elderly, and role-based triage gating.

*Medical accuracy:*
- Every result includes title, description, documentation (EPD-ready), explainer (patient communication), and sources with URLs.
- Antibiotic choices match NHG-Standaard: correct 1e/2e/3e keuze ordering, correct dosages, correct treatment durations.
- Nitrofurantoine: 5 dagen gezonde vrouwen, 7 dagen kwetsbaar/mannen/zwangeren. Correct.
- Ciprofloxacine for tissue invasion: 7 dagen vrouwen, 14 dagen mannen. Correct.
- Fosfomycine: eenmalig 3g (< 50 kg: 2g). Correct.
- Trimethoprim: 3 dagen gezond, 7 dagen kwetsbaar/mannen. Correct.
- Amoxicilline/clavulaanzuur children: weight-based (50/12.5 mg/kg). Correct.

*Safety mechanisms:*
- Contraindications presented as mandatory checkboxes that must be confirmed before treatment is revealed (`src/views/ResultPage.vue:88-126`). Strong safety pattern.
- Warnings include renal dose adjustments (eGFR thresholds), drug interactions (ACE-remmers + trimethoprim -> hyperkaliemie), and aorta-aneurysm risk for ciprofloxacine.
- Triage role correctly gates to U2 (tissue invasion) and U3 (vulnerable/complex) urgency referrals without showing treatment options.
- Catheter patients without tissue invasion correctly get "no treatment" (asymptomatische bacteriurie).
- Pregnant women with tissue invasion are correctly referred to gynaecologist.
- Triage rules are ordered before treatment rules in bacteriurie logic, ensuring triagists always get referral advice first.

**Remaining issues (medical safety):**

- **`flows/bacteriurie.yaml:357-378` -- treatmentTiCadWoman naming vs. conditions.** The question `treatmentTiCadWoman` suggests "catheter woman" but its condition gates on `riskAssessment == healthy`. This is functionally correct (a separate path exists for vulnerable+catheter at line 449-470), but the naming is misleading. Could confuse future maintainers.

- **`flows/bacteriurie.yaml:102-115` -- catheter question skipped for pregnant patients.** The `urinaryCatheter` question has conditions `riskAssessment != elderly` and `riskAssessment != pregnant`. A pregnant woman with a urinary catheter would be treated as "local + pregnant" without catheter-specific considerations (no catheter swap documented). **Deserves clinical verification.**

- **`flows/bacteriurie.yaml` -- elderly + tissue invasion + catheter pathway.** The catheter question is hidden for elderly patients. Elderly patients with tissue invasion and a catheter are routed to `treatmentTiElderlyWoman`/`treatmentTiElderlyMen` which do not include catheter swap documentation. The Verenso guideline recommends catheter exchange before antibiotics. **Gap in documentation output.**

- **No test suite.** `npm run test` passes with "No test files found". For a clinical tool, this is the single most significant gap. Every YAML flow path should have automated tests.

- **`flows/gezonde-vrouwen.yaml:141-156` -- first-match logic fragility.** Seven separate `not_includes` rules trigger independently. First-match semantics mean unchecking criterion 1 short-circuits without evaluating 2-7. Functionally correct but fragile if rule ordering changes.

- **No flow for recurrent UTI.** The NHG-Standaard has specific guidance for recidiverende cystitis (prophylaxis, cranberry, self-start therapy). Results mention "kweek als behandeling 2 keer gefaald heeft" but there is no dedicated flow.

## C. Improvement Opportunities

### Critical (medical safety)

1. **Add automated flow tests.** Every path through every YAML flow should have a test asserting the expected result. At minimum: strip (4 paths), sediment (3), dipslide (3), kweek (3), hematurie (3), leukocyturie (9), gezonde-vrouwen (5), bacteriurie (~50+ paths for behandelaar + triage). Estimated: 80+ test cases.

2. **Sanitize markdown HTML output.** Add DOMPurify or use marked's built-in HTML escaping. Affected: `src/views/QuestionnairePage.vue:85,103`.

3. **Verify pregnant + catheter clinical pathway.** Catheter question is skipped for pregnant patients (`flows/bacteriurie.yaml:107-108`). Confirm with clinician this is intentional.

4. **Add catheter swap documentation for elderly with tissue invasion.** The `treatmentTiElderlyWoman`/`treatmentTiElderlyMen` results should include catheter exchange instructions per Verenso guideline.

### High

5. **Fix PWA cache conflict.** Remove `Date.now()` cache-busting from `main.json` fetch. Rely on service worker precache versioning.

6. **Update vulnerable dependencies.** Run `npm audit fix`. Consider pinning `workbox-build` version.

7. **Make `npm audit` in CI blocking.** Remove `continue-on-error: true` or set high-severity threshold.

8. **Verify CI branch triggers.** Ensure `ci.yml` triggers on `main` (not just `master`).

### Medium

9. **Add flow versioning.** Include content hash in compiled output. Log active flow version with clinical decisions.

10. **Add step progress indicator.** Show "Stap 2 van 6" or progress bar.

11. **Add role-switch guard.** When role changes mid-questionnaire, warn and offer restart.

12. **Remove `passWithNoTests: true`** so missing tests cause visible CI failure.

### Low

13. **Extract QuestionnairePage composables.** Split popover logic, keyboard handling, navigation into separate files.

14. **Add usage analytics.** Capture anonymized flow completion events.

15. **Convert `vite.config.js` to TypeScript.**

## D. Feature/Fix Specs

### SPEC-001: Clinical Flow Test Suite

**Job Story:** When a developer changes a YAML flow, they want automated verification that all decision paths produce correct results, so that clinical errors are caught before deployment.

**Given** a compiled `main.json` from all YAML flows
**When** running `npm test`
**Then** every reachable answer combination should resolve to a defined result key
**And** the result key should match the expected clinical outcome
**And** role-based branching should produce different results where applicable

**Implementation:**
- Create `src/__tests__/flows/` directory
- One test file per flow (e.g., `strip.test.ts`, `bacteriurie.test.ts`)
- Import `validateConditions` and `determineOutcome` from `decision-engine-core`
- Load compiled JSON at test time
- Data-driven: generate test cases from flow structure
- Estimated effort: 2-3 days

### SPEC-002: Markdown Sanitization

**Given** a markdown string from flow data
**When** rendered via `v-html`
**Then** dangerous HTML tags (script, iframe, event handlers) are stripped

**Implementation:**
- Install `dompurify` (~4KB gzipped)
- Create `src/lib/markdown.ts` with `safeMarkdown(text: string): string`
- Replace direct `marked.parse()` calls in QuestionnairePage
- Add unit test with XSS payloads
- Estimated effort: 1 hour

### SPEC-003: Role-Switch Guard

**Given** a questionnaire is in progress
**When** the user clicks the role toggle
**Then** show confirmation: "Rol wisselen herstart de vragenlijst. Doorgaan?"
**And** if confirmed, clear answers and restart
**And** if cancelled, keep current role and answers

**Implementation:**
- Add `isQuestionnaireActive` computed to questionnaireStore
- Modify `RoleToggle.vue` to check active state before toggling
- Add confirmation modal
- Estimated effort: 0.5 days

## H. Overall Assessment

urinest.rip is a well-architected, clinically thorough decision aid. The YAML flow content is impressively detailed, covering edge cases like catheter patients, elderly with/without symptoms, pregnant women, and children -- all with correct antibiotic choices, dosages, durations, contraindications, and renal dose adjustments per NHG and Verenso guidelines. The contraindication checkbox gate before treatment display is an excellent safety pattern.

The architecture is clean and maintainable. The role-based system (triage vs. behandelaar) elegantly gates treatment options at the flow level. Error handling, logging, and operational observability are production-grade.

**The critical gap is the complete absence of automated tests.** For a tool that influences clinical decisions about antibiotic prescribing, every flow path must be tested. This is the single most impactful improvement that should be prioritized immediately.
