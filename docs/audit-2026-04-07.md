## Dimension Scores

### 1. Architecture -- 4/5

**Strengths:**
- Clean separation: YAML flows (clinical content) vs. decision-engine-core (runtime logic) vs. Vue UI
- Normalized Pinia store with proper entity maps (`questionnaireStore.ts:40-44`)
- PWA with prompt-based service worker updates (`vite.config.js:24`)
- Brotli + gzip compression configured (`vite.config.js:59-68`)
- Role system (`_role`) cleanly injected into condition evaluation (`questionnaireStore.ts:183-189`)

**Weaknesses:**
- Decision-engine-core is a local tarball (`decision-engine-core-1.0.0.tgz`) -- no version pinning, no audit visibility
- Stale `.nuxt/` directory present in repo root (leftover from Nuxt migration)

### 2. Security -- 3/5

**Strengths:**
- `.env` properly gitignored and verified not tracked
- CI pipeline includes secret scanning (JWT pattern grep) and `.env` tracking check (`ci.yml:46-57`)
- eslint-plugin-security enabled with sensible overrides (`eslint.config.js:33`)
- Supabase auth for admin routes (`router/index.ts:91-99`)

**Weaknesses:**
- **CRITICAL: `.env` contains unrelated API keys** -- OPENAI_API_KEY and ANTHROPIC_API_KEY are stored in this project's `.env` file. While not tracked by git, these keys are unrelated to urinest.rip and should not be present. If this `.env` is ever accidentally committed or the machine is compromised, two separate API accounts are exposed.
- **v-html used without sanitization** -- `QuestionnairePage.vue:84,103` renders markdown via `marked.parse()` directly into `v-html`. The input is from YAML flows (trusted), but no DOMPurify or similar sanitizer is used. If a flow ever contains user-generated content or is modified maliciously, XSS is possible.
- Source maps uploaded to Supabase Storage in CI (`ci.yml:118-140`) -- ensure the bucket has proper access control to prevent reverse-engineering of the production build.
- `vue/no-v-html` rule explicitly disabled in eslint (`eslint.config.js:49`)

### 3. Performance -- 5/5

**Strengths:**
- Brotli + gzip pre-compression for all assets
- Service worker with precaching (`workbox.globPatterns`)
- Lazy-loaded routes for admin pages (`router/index.ts:75-76`)
- CSS containment on result page (`ResultPage.vue:347 -- contain: layout style paint`)
- Skeleton loading states for perceived performance (`QuestionnairePage.vue:4-13`, `ResultPage.vue:23-49`)
- Cache-busted fetch for main.json (`questionnaireStore.ts:143 -- ?t=Date.now()`)
- Touch-optimized with `touch-action: manipulation`

**No issues identified.** Excellent performance engineering for a clinical tool where speed matters.

### 4. Reliability -- 3/5

**Strengths:**
- Unified error handler with classification (`errors.ts:14-45`)
- Structured logging with sink system and breadcrumbs (`logger.ts`)
- Supabase-based error persistence for production monitoring
- Service worker ensures offline availability
- Router guards handle missing data gracefully (`router/index.ts:27-62`)

**Weaknesses:**
- **Zero test files** -- `vitest` is configured with `passWithNoTests: true` (`vite.config.js:19`). For a medical decision support tool, this is a significant reliability gap. No automated verification of clinical flow logic, condition evaluation, or result mapping.
- **No YAML validation tests** -- while the build plugin validates YAML structure, there are no tests that verify specific clinical paths (e.g., "nitriet positive -> redirect to bacteriurie").
- `determineResult()` in `QuestionnairePage.vue:254-282` navigates to `/error` on null outcome without logging which answers/flow led to the dead end.

### 8. Clinical Correctness & Medical Safety -- 4/5

**Strengths:**
- **Flow logic is comprehensive and well-structured:**
  - Strip flow correctly gates: nitriet+ -> bacteriurie redirect; nitriet- leuko+ -> leukocyturie; nitriet- leuko- ery+ -> hematurie; all negative -> no abnormality
  - Bacteriurie flow covers all NHG/Verenso patient groups: healthy, vulnerable, pregnant, men, children, elderly (symptomatic/asymptomatic), with/without catheter
  - Tissue invasion correctly routes pregnant patients to gynaecologist referral
  - Triage rules correctly fire before treatment rules (logic order in bacteriurie.yaml:1063-1092)
  - CAD (catheter) patients with local infection correctly get "no treatment" result
  - Elderly asymptomatic patients correctly get "no antibiotics" recommendation
- **Antibiotic choices match NHG-Standaard (2025 version):**
  - Healthy women: nitrofurantoine 1e keus (5d), fosfomycine 2e, trimethoprim 3e
  - Men: nitrofurantoine 1e (7d, off-label), trimethoprim 2e (7d)
  - Pregnant: nitrofurantoine 1e (7d), amoxicilline/clavulaanzuur 2e
  - Children: nitrofurantoine 1e (5d), amoxicilline/clavulaanzuur 2e
  - Tissue invasion: ciprofloxacine 1e (7-14d depending on group), amox/clav 2e, cotrimoxazol 3e
- **Contraindications and warnings properly recorded** (eGFR thresholds, G6PD, drug interactions)
- **Dosages correct** against NHG-Standaard and Farmacotherapeutisch Kompas
- **Review dates documented** in AboutPage.vue (all guidelines reviewed February 2026)
- **Sources linked per result** -- every clinical recommendation has NHG/Verenso/NVKC/NVU references

**Issues and edge cases:**

1. **Missing triage rule for triagist + local + healthy + no catheter** -- In `bacteriurie.yaml:1064-1092`, triagist rules cover tissue invasion (U2), and all risk groups for local (U3), including `healthy + catheter`. But there is NO triage rule for `triagist + local + healthy + no catheter`. This means a triagist handling a healthy woman with cystitis without catheter will fall through to the treatment selection questions, which are gated by `_role != triagist`. The triagist will see no next question and hit a dead end (no matching logic rule), leading to the error page. **This is a clinical flow bug.**

2. **Gezonde-vrouwen flow condition evaluation order** -- The `not_includes` rules (lines 143-156) each independently show `ruleNotApplicable`. This is correct because the engine evaluates top-down and stops at the first match. However, this creates 7 identical result displays. More importantly, it means a user who checks 6 of 7 boxes still sees "not applicable" -- which is correct but may confuse users who expected partial credit.

3. **Leukocyturie: child population has no sediment option** -- In `leukocyturie.yaml:47-60`, the `followUpChild` question only offers dipslide and urinekweek, while the general population also gets urine sediment. This matches NHG guidance (sediment is less common for children) but is not explicitly documented in the flow.

4. **Hematurie proteinuria: extensive documentation text** -- The `documentation` field for `blood.proteinuria` (`hematurie.yaml:48`) contains multi-line clinical instructions that may overflow the copy-to-clipboard EPD documentation format. Consider whether this should be structured differently.

5. **Duplicate result reuse** -- Elderly symptomatic female patients are mapped to `uti.local.vulnerable.{0,1,2}` results, and elderly symptomatic males to `uti.local.men.{0,1,2}`. This is clinically correct (same treatment) but the result titles say "Kwetsbare patient" and "Man" respectively, not "Kwetsbare oudere" -- minor labeling inconsistency.

6. **Nitrofurantoine during pregnancy timing** -- The NHG-Standaard warns against nitrofurantoine use near term (contraindicated in last trimester). The flow does not include a trimester check. The `contraindications` for `uti.local.pregnant.0` only lists eGFR and G6PD.
