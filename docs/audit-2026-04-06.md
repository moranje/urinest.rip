## Detailed Analysis

### 1. Correctness (4/5)

**Strengths:**
- All 8 YAML flows compile without errors via decision-engine-core Vite plugin
- Every logic branch in every flow terminates in either a `show` (display result) or `redirect` (to another flow)
- Role-based branching (`_role == triagist` vs `behandelaar`) is correctly injected via `getEnhancedAnswers()` at `src/store/questionnaireStore.ts:183-189`
- Strip flow correctly cascades: nitriet+ -> bacteriurie, nitriet- leuko+ -> leukocyturie, nitriet- leuko- ery+ -> hematurie, all negative -> noConclusiveAbnormality
- Condition evaluation delegates to decision-engine-core `validateConditions` and `determineOutcome`
- Question visibility correctly gated by conditions (e.g., leukocytes question only shown when nitriet is negative, `strip.yaml:26-27`)

**Concerns:**
- `passWithNoTests: true` in `vite.config.js:19` -- CI exits 0 with zero tests, providing false confidence
- `determineResult()` at `QuestionnairePage.vue:272` splits outcome on `:` delimiter -- fragile if result keys ever contain colons
- `compiledMarkdown()` at `QuestionnairePage.vue:347` casts `marked.parse()` to `string` but `marked.parse` can return `Promise<string>` if async extensions are configured -- works today but brittle
- Catheter question (`bacteriurie.yaml:102-115`) conditions exclude elderly AND pregnant but uses `!=` operators -- if a new risk group were added, it might incorrectly show the catheter question

### 2. Medical Safety (4/5)

**Strengths:**
- All antibiotic results include contraindications as interactive checkboxes gating treatment display (`ResultPage.vue:88-126`)
- Dosage information is drug-specific with duration, frequency, and dose (e.g., "Nitrofurantoïne, 5 dagen, 2 dd 100 mg mga of 4 dd 50 mg")
- eGFR-based warnings for renal-adjusted dosing:
  - Nitrofurantoïne: contraindicated at eGFR < 30, warning at eGFR 30-50 (`bacteriurie.yaml:564-567`)
  - Trimethoprim: dose adjustment at eGFR 10-30 (`bacteriurie.yaml:601-602`)
  - Ciprofloxacine: dose adjustment at eGFR 30-60 and < 30 (`bacteriurie.yaml:771`)
- Drug interactions flagged: trimethoprim + ACE-remmers/ARBs/spironolacton -> hyperkaliemie (`bacteriurie.yaml:602`)
- Pregnant women with tissue invasion correctly redirected to gynecologist (`bacteriurie.yaml:515-524`)
- Triage role shows urgency-based referrals: U2 for tissue invasion, U3 for vulnerable patients (`bacteriurie.yaml:493-511`)
- Asymptomatische bacteriurie bij kwetsbare ouderen: correctly advises against antibiotics (`bacteriurie.yaml:526-535`)
- CAD (catheter a demeure) patients without tissue invasion: correctly advises no treatment (`bacteriurie.yaml:537-544`)
- Sources link to NHG-Standaard, Verenso, NVKC, NVU, Thuisarts.nl, and NHG-TriageWijzer

**Concerns:**
- **Pediatric dosing lacks weight input**: "5 tot 6 mg/kg lichaamsgewicht" is text-only (`bacteriurie.yaml:734`). No calculator or validation. Appropriate for a decision aid but a potential source of dosing errors in practice.
- **Ciprofloxacine duration discrepancy**: Result `uti.tissueInvasion.healthy.0` at `bacteriurie.yaml:763` states "7 dagen" per NHG, but Verenso recommends "10 dagen" for vulnerable elderly women. The treatment question description mentions this (`bacteriurie.yaml:415`) but the result text does not repeat it. Elderly women get result `uti.tissueInvasion.vulnerable.0` via logic redirect at line 1206, which correctly states ciprofloxacine but uses the same "7 dagen" from NHG.
- **Fosfomycine breastfeeding warning**: Listed as contraindication ("Geef vrouwen die borstvoeding geven bij voorkeur geen fosfomycine") but phrased as preference ("bij voorkeur"), not absolute contraindication. Clinically accurate but may confuse users about severity.
- **No allergy recording**: Treatment options say "controleer eerst op allergieën" in description text, but the app has no mechanism to record or remember allergies across sessions.
- **Guideline staleness**: Reviews date to February 2026 (`AboutPage.vue:74-100`). Now April 2026 -- still within typical review cycles but should be monitored.

### 3. Security (3/5)

**Strengths:**
- CI secret scanning via grep for JWT patterns (`ci.yml:47-50`)
- `.env` not tracked by git (verified: `.gitignore` line 4)
- Supabase credentials via environment variables only
- ESLint security plugin active (`eslint.config.js:32-33`)
- Admin routes protected by auth guard (`router/index.ts:91-99`)
- Source maps uploaded to private Supabase Storage, not served publicly

**Concerns:**
- **14 npm vulnerabilities** including 6 high-severity undici CVEs (WebSocket overflow, HTTP smuggling, CRLF injection). While undici is primarily a server-side concern, it is bundled via Vite's development dependencies and could affect SSR or build tooling.
- **yaml package vulnerable** to stack overflow via deeply nested collections (moderate). Since YAML is only parsed at build time by decision-engine-core, this is exploitable only if malicious YAML were introduced -- low risk in practice but should be patched.
- **v-html with disabled lint rule**: `vue/no-v-html: 'off'` in `eslint.config.js:49`. Content comes from trusted YAML, but the disabled rule means future `v-html` usage won't be flagged.
- **Real `.env` file on disk** (`/Users/martien/Sync/Projects/code/urinest.rip/.env`) contains Supabase URL and anon key. Standard practice but noted.
- **`detect-unsafe-regex: 'off'`** in eslint.config.js:37 -- disabled for UA parsing regexes in `error-context.ts`. Justified but should be scoped to that file only.
- **No CSP headers** configured in `netlify.toml` or `index.html`. The app serves user-facing medical content; a Content-Security-Policy would harden against injection.

### 4. Reliability (3/5)

**Strengths:**
- Global Vue error handler captures all component errors (`main.ts:14-16`)
- Unhandled promise rejection handler (`main.ts:18-21`)
- Structured error classification with Dutch user messages (`errors.ts:58-118`)
- Log sink with buffered persistence, circuit breaker (max 5 failures), and flush-on-unload (`log-sink.ts:75-107`)
- PWA with service worker for offline support (`vite.config.js:24-58`)
- Cache-busting on `main.json` fetch with `Date.now()` (`questionnaireStore.ts:143`)
- Supabase client gracefully degrades to null if env vars missing (`supabase/client.ts:18-19`)

**Concerns:**
- **Zero test files**: `vitest run` reports "No test files found" and exits 0 due to `passWithNoTests: true`. No unit tests for the decision engine integration, answer management, condition evaluation, or result determination.
- **No E2E tests**: No Playwright or Cypress tests for clinical paths. A single wrong condition in YAML could send patients down incorrect treatment paths with no automated detection.
- **`flushLogs()` on beforeunload** (`main.ts:31`): Relies on `async/await` during page unload, which browsers may not complete. Could use `navigator.sendBeacon` for reliability.
- **Session storage for session ID** (`log-sink.ts:24-32`): Cleared on browser close, making cross-session error correlation impossible. Acceptable trade-off for privacy.

### 5. Performance (4/5)

**Strengths:**
- Brotli + gzip pre-compression via vite-plugin-compression (`vite.config.js:59-68`)
- Lazy-loaded routes: QuestionnairePage, AdminLogin, LogDashboard (`router/index.ts:21,75,80`)
- PWA workbox caching of all static assets (`vite.config.js:54-57`)
- CSS `contain: layout style paint` on scrollable areas (`App.vue:70`, `ResultPage.vue:347`)
- Skeleton loading states prevent layout shift (`QuestionnairePage.vue:4-14`, `ResultPage.vue:23-49`)

**Concerns:**
- `main.json` fetched with `?t=Date.now()` bypasses all caching (`questionnaireStore.ts:143`). This is ~196KB (12KB brotli) on every visit. Could use ETag/If-None-Match or service worker cache-first strategy.
- `bacteriurie.yaml` compiles to a large portion of main.json (1225 lines of YAML). Not a runtime concern but contributes to initial load.

**Strengths:**

- Normalized Pinia store pattern with separate state maps for questionnaires, questions, steps, results, logic (`questionnaireStore.ts:40-44`)
- Proper separation: stores handle state, views handle presentation, lib handles utilities

## Opportunities

### SPEC-U01: Critical path testing for clinical flows

**Problem:** Zero automated tests for the most safety-critical part of the app -- the clinical decision logic. A single YAML typo could route patients to wrong treatment.

**Solution:** Create vitest test files that exercise each flow's logic rules with known input -> expected output pairs. Start with the highest-risk paths: bacteriurie tissue invasion referrals, pregnant pyelonefritis -> gynaecologist, elderly asymptomatic -> no treatment.

**Scope:** ~200 LOC across 3-4 test files. Remove `passWithNoTests: true` from vite.config.js.

**Files:** `src/__tests__/flows/bacteriurie.test.ts`, `src/__tests__/flows/strip.test.ts`, `src/__tests__/flows/leukocyturie.test.ts`

### SPEC-U02: npm audit remediation

**Problem:** 14 vulnerabilities (6 high) in undici, yaml, workbox-build. CI `npm audit` runs with `continue-on-error: true` so these pass silently.

**Solution:** Run `npm audit fix` to patch undici and yaml. Evaluate workbox-build/vite-plugin-pwa update. Remove `continue-on-error: true` from CI audit step or set a threshold.

**Scope:** 1 command + CI config change.

**Files:** `package-lock.json`, `.github/workflows/ci.yml:43`

### SPEC-U03: Deduplicate result definitions between gezonde-vrouwen and bacteriurie

**Problem:** `uti.local.healthy.0` through `uti.local.healthy.3` are defined identically in both `gezonde-vrouwen.yaml` and `bacteriurie.yaml`. Any dosage or contraindication change must be made in two places.

**Solution:** Either have `gezonde-vrouwen` redirect to `bacteriurie` for treatment (maintaining the current redirect pattern), or extract shared results to a common results file that the build plugin merges.

**Scope:** ~100 lines removed from gezonde-vrouwen.yaml, logic rules updated to redirect.

**Files:** `flows/gezonde-vrouwen.yaml`, potentially `flows/bacteriurie.yaml`

### SPEC-U04: YAML schema validation

**Problem:** Flow YAML has no schema validation beyond "does it compile." A missing `sources` array, typo in a condition operator, or incorrect result key would only be caught at runtime.

**Solution:** Create a JSON Schema for the YAML flow format and validate during build. Add IDE-level validation via `.vscode/settings.json` with YAML language server.

**Scope:** ~150 LOC schema file + build plugin modification.

**Files:** `flows/schema.json`, vite plugin config

### SPEC-U05: Add Content-Security-Policy headers

**Problem:** No CSP configured. The app serves medical content and uses `v-html` for markdown rendering. A CSP would provide defense-in-depth against XSS.

**Solution:** Add CSP headers to `netlify.toml` allowing `self`, inline styles (for design tokens), and external links to NHG/Verenso/NVKC/NVU.

**Scope:** ~10 lines in netlify.toml.

**Files:** `netlify.toml`

### SPEC-U06: Fix CI branch trigger

**Problem:** CI workflow triggers on `master` (`ci.yml:4-5`) but the active branch may be `main`. This could mean CI never runs automatically.

**Solution:** Update workflow triggers to reference both `main` and `master`, or just `main` if that is the canonical branch.

**Scope:** 2-line change.

**Files:** `.github/workflows/ci.yml:4-5`

### SPEC-U07: Refactor bacteriurie.yaml logic rules

**Problem:** The logic section (lines 1063-1225) of bacteriurie.yaml contains 163 lines of highly repetitive rule definitions. Each treatment option for each patient group generates a separate rule that differs only in the treatment question key and value.

**Solution:** Extend decision-engine-core to support parameterized logic rules or template expansion, reducing the 163 lines to ~40 template lines.

**Scope:** Requires decision-engine-core changes. Medium effort.

**Files:** `decision-engine-core/`, `flows/bacteriurie.yaml`

### SPEC-U08: Use navigator.sendBeacon for log flush on unload

**Problem:** `flushLogs()` is called on `beforeunload` via async/await (`main.ts:31`). Browsers may terminate the page before the async operation completes, losing error logs.

**Solution:** Detect `beforeunload` and use `navigator.sendBeacon` with a JSON payload instead of the Supabase client.

**Scope:** ~20 LOC in log-sink.ts.

**Files:** `src/lib/log-sink.ts`

## Summary

The application is a well-structured clinical decision aid with thorough coverage of NHG/Verenso guidelines for urinalysis. The YAML-based flow system with role-based branching (behandelaar vs triagist) is architecturally sound. Medical safety is strong: contraindications gate treatment display, dosages are specific, and sources are linked.

The three most pressing concerns are:

1. **Zero automated tests** for clinical decision logic (SPEC-U01) -- the highest-risk gap in a medical application
2. **14 npm vulnerabilities** including 6 high-severity undici CVEs (SPEC-U02) -- quick fix via `npm audit fix`
3. **Result duplication** between flows creating drift risk for treatment data (SPEC-U03)

Overall score: **3.63/5** with 5 critical/medium issues and 8 improvement specs.
