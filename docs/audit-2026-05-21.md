**Correction of SPEC-UR01 from previous audit:**

The previous audit reported a triagist dead-end for `triagist + local + healthy + no catheter`. After detailed re-analysis: `treatmentLocalHealthy` (line 119-142) intentionally lacks the `_role != triagist` condition that gates all other treatment questions. This means a triagist evaluating a healthy woman with local cystitis without catheter DOES see the treatment question and gets routed to a valid result via the treatment logic rules (lines 1116-1123). This is NOT a dead-end.

However, this creates a **design inconsistency**: all 14 other treatment questions are gated by `_role != triagist` (lines 149, 174, 192, 209, 228, 252, 275, 298, 320, 345, 362, 385, 410, 434, 453), but `treatmentLocalHealthy` is not. This appears intentional (healthy women with uncomplicated cystitis may be triaged directly), but the asymmetry should be explicitly documented.

The NHG-Standaard warns explicitly against nitrofurantoine near delivery (contraindicated from 36 weeks). 2. **Minor: treatmentLocalHealthy triage-gate asymmetry** -- `treatmentLocalHealthy` (line 119) lacks `_role != triagist` unlike all other 14 treatment questions. 3. **Minor: Elderly result labeling** -- Elderly symptomatic women map to `uti.local.vulnerable.{0,1,2}` (title "Kwetsbare patient") and elderly symptomatic men to `uti.local.men.{0,1,2}` (title "Man"). Neither says "Kwetsbare oudere".

### SPEC-UR02: DOMPurify sanitization for v-html

**Type:** Security hardening
**Impact:** High -- prevents potential XSS if YAML flow content is ever compromised
**Effort:** S (2 hours)
**Status:** Open (50 days)

**Problem:** `src/views/QuestionnairePage.vue:173,192` -- `v-html="compiledMarkdown(...)"` renders `marked.parse()` output without sanitization. Input is from own YAML flows (trusted), but defense-in-depth requires a DOMPurify layer.

**Solution:** Install `dompurify` and wrap all `marked.parse()` output:

```typescript
import DOMPurify from 'dompurify'
const compiledMarkdown = (text: string | undefined): string =>
  text ? DOMPurify.sanitize(marked.parse(text) as string) : ''
```

**Acceptance Criteria:**

Given a YAML flow description contains `<script>alert('xss')</script>`
When the markdown is rendered in QuestionnairePage
Then the script tag is stripped from the output

Given a YAML flow description contains valid markdown with links
When the markdown is rendered
Then links are preserved and functional

- [ ] Install dompurify: `npm install dompurify`
- [ ] Install types: `npm install -D @types/dompurify`
- [ ] Wrap `marked.parse()` with `DOMPurify.sanitize()` in `QuestionnairePage.vue:558-559`
- [ ] Reconsider `vue/no-v-html` ESLint rule or add inline comment explaining sanitization

## Previous audit SPEC-UR01 correction

The previous audit (2026-04-09) reported a **triagist dead-end** for `triagist + local + healthy + no catheter` as a critical issue. Upon detailed re-analysis of the bacteriurie.yaml flow logic:

1. Triage rules (lines 1067-1092) do NOT match this combination (line 1091 requires `urinaryCatheter == yes`)
2. The `treatmentLocalHealthy` question (line 119) intentionally lacks `_role != triagist`, so it IS shown to triagists
3. The treatment logic rules (lines 1116-1123) match for any role, routing to valid results

**Conclusion:** This is NOT a dead-end. The triagist can select a treatment and gets a valid result. The previous audit's SPEC-UR01 was based on an incorrect assumption that treatment questions would be hidden for triagists in this case. The actual behavior is that healthy women with uncomplicated cystitis are the one exception where triagists can handle treatment selection directly.

This is now reclassified as a **design documentation issue** (SPEC-UR08) rather than a dead-end bug.
