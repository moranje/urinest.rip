## Per-Dimension Analysis

### 1. Architecture -- 4/5

**Strengths:**
- Clean three-layer separation: YAML clinical content / decision-engine-core runtime / Vue 3 UI (`flows/` -> `vite.config.js:23` plugin -> `public/main.json` -> `questionnaireStore.ts:143`)
- Normalized Pinia store with entity maps and loading promise deduplication (`questionnaireStore.ts:134-159`)
- Role system (`_role`) cleanly injected into condition evaluation (`questionnaireStore.ts:183-189`)
- PWA with prompt-based service worker updates and workbox precaching (`vite.config.js:24-58`)

**Remaining issues:**
- `decision-engine-core` is a local tarball (`decision-engine-core-1.0.0.tgz`) with no version pinning, audit visibility, or documented update process
- Stale `.nuxt/` directory (leftover from Nuxt migration) still present, adds confusion and may contribute `defu` dependency vulnerability

### 2. Security -- 3/5

**Strengths:**
- `.env` properly gitignored; CI verifies not tracked (`ci.yml:52-57`)
- CI secret scanning for JWT patterns (`ci.yml:46-51`)
- eslint-plugin-security enabled with recommended rules (`eslint.config.js:32-34`)
- Supabase auth guard for admin routes (`router/index.ts:91-99`)

**Remaining issues:**
- **`.env` bevat 3 ongebruikte API keys**: OPENAI_API_KEY, ANTHROPIC_API_KEY, DEEPSEEK_API_KEY -- geen van deze wordt door urinest.rip gebruikt. Vergroot de blast radius bij een lek.
- **v-html zonder DOMPurify**: `QuestionnairePage.vue:84,103` rendert `marked.parse()` output direct in `v-html`. Input komt uit YAML flows (trusted), maar geen DOMPurify-laag beschermt tegen toekomstig compromised flow content.
- **`vue/no-v-html` ESLint-regel expliciet uitgeschakeld** (`eslint.config.js:49`)
- **15 dependency vulnerabilities** (13 high) -- Vite 7.2.4 heeft 3 CVEs (path traversal, fs.deny bypass, WebSocket file read), fix beschikbaar op 7.3.2
- **Source maps naar Supabase Storage** -- bucket access control moet geverifieerd worden

### SPEC-UR03: DOMPurify sanitization voor v-html

**Type:** Security hardening
**Impact:** High -- voorkomt potentiele XSS als YAML flow content ooit gecompromitteerd wordt
**Effort:** S (2 uur)

**Problem:** `src/views/QuestionnairePage.vue:84,103` -- `v-html="compiledMarkdown(...)"` rendert `marked.parse()` output zonder sanitization. Input komt uit eigen YAML flows (trusted), maar een defense-in-depth strategie vereist een DOMPurify-laag.

**Solution:** Installeer `dompurify` en wrap alle `marked.parse()` output:

```typescript
import DOMPurify from 'dompurify'
const compiledMarkdown = (text: string | undefined): string =>
  text ? DOMPurify.sanitize(marked.parse(text) as string) : ''
```

**Acceptance Criteria:**

Given een YAML flow description bevat `<script>alert('xss')</script>`
When de markdown wordt gerenderd in QuestionnairePage
Then wordt de script tag gestript uit de output

Given een YAML flow description bevat geldige markdown met links
When de markdown wordt gerenderd
Then worden links behouden en functioneel

**Checklist:**
- [ ] Installeer dompurify: `npm install dompurify`
- [ ] Installeer types: `npm install -D @types/dompurify`
- [ ] Wrap `marked.parse()` met `DOMPurify.sanitize()` in QuestionnairePage.vue
- [ ] Heroverweeg `vue/no-v-html` ESLint-regel of voeg inline comment toe die sanitization verklaart
