## C. Dimension Analysis

### 1. Architecture (4/5)

**Strengths:**
- Clean three-layer separation: YAML flows (clinical content) -> decision-engine-core Vite plugin (build-time compilation) -> Vue components (presentation).
- Normalized Pinia store with flat lookup maps for O(1) access to questions, steps, results, logic rules.
- Role-based condition injection (`_role`) cleanly separates triage vs. behandelaar pathways at the flow level.
- Cross-flow redirects work elegantly (strip -> bacteriurie, leukocyturie -> dipslide/sediment/kweek).
- Well-structured error handling pipeline: `errors.ts` (classification) -> `logger.ts` (structured output) -> `log-sink.ts` (batched persistence) -> Supabase.
- Breadcrumb ring buffer captures navigation trail for error context.

**Issues:**
- `questionnaireStore.ts:143`: Cache-busting `Date.now()` query parameter on `main.json` defeats service worker precaching. The workbox `globPatterns` includes `**/*.json`, creating a version mismatch between precached and network-fetched copies. **Unchanged since previous audit.**
- `decision-engine-core-1.0.0.tgz`: Local tarball with no visible source repository, changelog, or update mechanism.
- Single monolithic `main.json` (~196KB) means any flow change invalidates the entire cached payload.

### 2. Security (3/5) -- downgraded from 4

**Strengths:**
- CI pipeline includes JWT secret scanning, `.env` tracking check.
- Supabase credentials via environment variables, never hardcoded.
- ESLint security plugin with sensible rule configuration.
- Admin routes protected by Supabase auth guard.
- Source maps uploaded to private Supabase storage, not served to clients.
- oxlintrc bans eval/implied-eval/new Function/script URLs.

**Issues (unchanged from previous audit):**
- **`v-html` without sanitization.** `QuestionnairePage.vue:85,103` renders `marked.parse()` output as raw HTML. While YAML is author-controlled, `marked` does not sanitize by default. If the build pipeline were compromised or a YAML file were tampered with, arbitrary JavaScript execution is possible in the browser of every clinician using the tool.
- **12 npm audit vulnerabilities remain unaddressed.** High-severity: `undici` (HTTP smuggling, WebSocket overflow, memory DoS -- 6 advisories), `rollup` (arbitrary file write via path traversal), `serialize-javascript` (RCE via crafted objects), `flatted` (prototype pollution), `minimatch` (ReDoS), `picomatch` (ReDoS). Most fixable via `npm audit fix`.
- **CI `npm audit` is non-blocking** (`continue-on-error: true` in `ci.yml:43`). Builds succeed despite high-severity findings.
- **CI branch mismatch.** `ci.yml` triggers on `master` branch but local branch is `main`. If GitHub default branch is `main`, CI may not trigger on pushes.
- **No Content Security Policy.** `index.html` has no CSP meta tag or header. External script (`stats.oranje.wtf`) is loaded without subresource integrity.
- **`.env` file has 644 permissions** (readable by all users on the machine). Should be 600.

### 3. Performance (4/5)

**Strengths:**
- Dual compression: Brotli + gzip via vite-plugin-compression (main bundle 90KB brotli).
- Code splitting: QuestionnairePage (~14KB brotli) and admin views lazy-loaded.
- CSS design tokens via custom properties, no runtime CSS-in-JS overhead.
- Skeleton loading states in QuestionnairePage and ResultPage for perceived performance.
- `contain: layout style paint` for paint isolation on scrollable content.
- Google Fonts loaded via `media="print" onload` pattern to prevent render blocking.

**Issues:**
- `fetch('/main.json?t=' + Date.now())` forces network request every app load, defeating browser and service worker caching. **Unchanged since previous audit.**
- `marked` library (~17KB gzipped) imported for rendering short inline markdown links in question descriptions. A lighter markdown-link-only parser would reduce bundle size.
- `main.json` is 196KB uncompressed (12KB brotli). Acceptable but could be split per flow for incremental caching.

### 4. Reliability / Clinical Correctness (3/5) -- CRITICAL, downgraded from 4

**This is the most important dimension for a clinical decision tool.**

**Strengths -- Flow coverage and medical accuracy:**

*Antibiotic choices verified against NHG-Standaard (2024 revision):*
- Nitrofurantoine: 5 dagen gezonde vrouwen, 7 dagen kwetsbare/mannen/zwangeren/kinderen. **Correct.**
- Fosfomycine: eenmalig 3g (< 50 kg: 2g). **Correct.**
- Trimethoprim: 3 dagen gezond, 7 dagen kwetsbaar/mannen. **Correct.**
- Ciprofloxacine tissue invasion: 7 dagen vrouwen, 14 dagen mannen. **Correct.**
- Amoxicilline/clavulaanzuur tissue invasion: 10 dagen vrouwen, 14 dagen mannen. **Correct.**
- Children local: nitrofurantoine 5-6 mg/kg in 4 giften, max 200 mg/dag. **Correct.**
- Children tissue invasion: amoxicilline/clavulaanzuur 50/12.5 mg/kg in 3 giften. **Correct.**
- Cotrimoxazol children TI: 30/6 mg/kg/dag in 2 giften. **Correct.**

*Safety mechanisms:*
- Contraindication checkboxes gate treatment display (`ResultPage.vue:88-126`). Treatment is hidden until all contraindications are reviewed. **Excellent safety pattern.**
- Renal dose adjustments documented (eGFR thresholds for nitrofurantoine, trimethoprim, ciprofloxacine, amoxicilline/clavulaanzuur).
- Drug interaction warnings (ACE-remmers + trimethoprim -> hyperkaliemie, cumarine + cotrimoxazol).
- Aorta-aneurysm risk warning for ciprofloxacine.
- Triage rules ordered before treatment rules in bacteriurie logic.
- Pregnant women with tissue invasion correctly referred to gynaecologist.
- Catheter patients without tissue invasion correctly get "no treatment" (asymptomatische bacteriurie).
- Elderly asymptomatic patients correctly get "no antibiotics."

**Issues -- CRITICAL for a clinical tool:**

1. **ZERO automated tests.** `npm test` finds no test files. `passWithNoTests: true` masks this entirely. For a tool that guides antibiotic prescribing for patients including children, pregnant women, and elderly, this is unacceptable. Every decision path must have automated verification. **This was flagged as critical in the 2026-03-31 audit and remains unaddressed.**

2. **Pregnant + catheter pathway gap.** `bacteriurie.yaml:107-108`: The `urinaryCatheter` question is conditionally hidden for pregnant patients (`riskAssessment != pregnant`). A pregnant woman with a urinary catheter would be treated as "local + pregnant" without catheter-specific documentation (no catheter swap before antibiotics). **Still unverified clinically. Unchanged since previous audit.**

3. **Elderly + tissue invasion + catheter gap.** The catheter question is hidden for elderly patients. Elderly patients with tissue invasion and a catheter are routed to standard elderly treatment results that lack catheter exchange instructions. Verenso guideline explicitly recommends catheter exchange before antibiotics. **Unchanged since previous audit.**

4. **`treatmentTiCadWoman` naming vs. conditions.** `bacteriurie.yaml:357-378`: The question name suggests "catheter woman" but gates on `riskAssessment == healthy`. Functionally correct (a separate path exists for `vulnerable+catheter`), but confusing naming risks maintenance errors. **Unchanged since previous audit.**

5. **No flow for recurrent UTI.** NHG-Standaard has specific guidance for recidiverende cystitis (prophylaxis, cranberry, self-start therapy). Results mention "kweek als behandeling 2 keer gefaald heeft" but no dedicated flow exists for recurrent infections.

6. **`gezonde-vrouwen.yaml` logic fragility.** Seven separate `not_includes` rules (lines 143-156) trigger independently via first-match semantics. Rule reordering could silently change behavior without any test to catch it.

## D. Feature/Fix Specs

### SPEC-U01: Clinical Flow Test Suite (Critical -- medical safety)

**Job Story:** When a developer modifies a YAML decision flow, they need automated verification that all clinical decision paths produce correct results, so that incorrect antibiotic advice is never deployed to production.

**Given** compiled flow data from all 8 YAML files
**When** running `npm test`
**Then** every reachable answer combination resolves to a defined result key
**And** the result key matches the expected clinical outcome
**And** role-based branching produces different results for triagist vs. behandelaar
**And** cross-flow redirects resolve correctly (strip -> bacteriurie, etc.)
**And** contraindication data is present for all antibiotic results

**Implementation:**
- Create `src/__tests__/flows/` directory
- One test file per flow: `strip.test.ts`, `bacteriurie.test.ts`, etc.
- Import `validateConditions` and `determineOutcome` from `decision-engine-core`
- Load compiled JSON fixture at test time
- Data-driven test generation from flow structure
- Minimum: 80+ test cases covering all paths
- Remove `passWithNoTests: true` from `vite.config.js`
- Priority: **immediate** -- this is the #1 risk for a clinical tool
- Estimated effort: 2-3 days

### SPEC-U02: Markdown Sanitization (Critical -- security)

**Job Story:** When flow descriptions containing markdown are rendered in the browser, dangerous HTML must be stripped so that XSS is impossible even if YAML files are compromised.

**Given** a markdown string from flow YAML data
**When** rendered via `v-html` in QuestionnairePage
**Then** script tags, event handlers, iframes, and other dangerous HTML are stripped
**And** safe HTML (links, emphasis, lists) renders correctly

**Implementation:**
- Install `dompurify` (~4KB gzipped)
- Create `src/lib/markdown.ts`: `export function safeMarkdown(text: string): string { return DOMPurify.sanitize(marked.parseInline(text)) }`
- Replace `compiledMarkdown()` in `QuestionnairePage.vue` with `safeMarkdown()`
- Add unit test with XSS payloads: `<script>`, `<img onerror=...>`, `javascript:` URLs
- Estimated effort: 1 hour

### SPEC-U03: Fix npm Audit Vulnerabilities (High)

**Given** current `package.json` and `package-lock.json`

**And** CI blocks deployment on high-severity findings

**Implementation:**

**Given** a pregnant patient with a urinary catheter and local infection

**Then** the catheter question is presented
**And** the result includes catheter exchange documentation
**Or** the current behavior (skipping catheter question) is confirmed correct by a clinician and documented

### SPEC-U06: Content Security Policy (Medium -- security)

**Job Story:** When the app is served, a Content Security Policy header should restrict resource loading, so that XSS impact is mitigated even if code injection occurs.

**Given** the deployed application

### SPEC-U07: Touch-Friendly Info Popovers (Medium -- UX)

## J. Overall Assessment

urinest.rip remains a well-architected, clinically thorough decision aid with impressive YAML flow coverage. The antibiotic recommendations, dosages, durations, and contraindications have been verified against the NHG-Standaard and Verenso guidelines and are correct throughout. The contraindication checkbox gate, role-based triage gating, and cross-flow redirect system are excellent design patterns for a clinical tool.

However, the project's risk posture has worsened since the previous audit because none of the critical findings have been addressed in the intervening period:

1. **Zero automated tests** for a tool that guides antibiotic prescribing is the single most significant risk. Every YAML flow path must have automated regression tests before the next flow content change. This is non-negotiable for medical software.

2. **Unsanitized HTML rendering** (`v-html` with `marked.parse()`) creates a latent XSS vector. While the YAML content is author-controlled today, the attack surface exists if the build pipeline or source repository is compromised.

3. **12 unresolved npm vulnerabilities** (10 high) are addressable with `npm audit fix` and represent low-hanging fruit.

4. **Two unverified clinical edge cases** (pregnant + catheter, elderly + catheter + tissue invasion) need clinician sign-off.

The project is well-positioned to address these gaps quickly. The architecture is clean, the tooling is solid, and the clinical content is accurate. The primary need is engineering discipline: add tests, fix known vulnerabilities, and verify clinical edge cases.
